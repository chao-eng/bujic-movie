# 不想玩 PT，只想好好看个剧

去年我把群晖卖了，换了台 Mac mini 当家里的服务器，外挂两块 2T 硬盘。重新把 Jellyfin 装好的那天晚上，我想起以前在群晖里用过一个工具，想再找回来用——一查，它已经停更了。

这工具叫 nAStool，玩 NAS 的大概都听过。原作者转头去做了个更出名的项目：MoviePilot。

## 它没做错什么，只是不是做给我的

我兴冲冲把 MoviePilot 装上，初始化走到一半就卡住了：第一步要我接 PT 站点。

PT 这词，不混圈子的人多半没听过。大意就是种子站里分了个"会员级"，邀请制，不是想注册就注册。进了站还不算完，每个月有上传量和保种时长的考核，不达标就清号。这套规则我当然理解，正是有人常年挂着保种，冷门资源才活得下来。可理解归理解，我满脑子只有一个念头：我就想今晚吃完饭，打开 Jellyfin 点开《怪奇物语》新一季，谁爱每周盯上传量谁盯去。

所以当 MoviePilot 的界面里铺满下载器管理、站点维护、刷流这一类字眼时，我反而想通了一件事：这个项目一点没错，错的是我压根不是它的目标用户。MoviePilot 服务的是把下载当爱好、当生活一部分的那群人；我只是个想当观众的人。

至于文件是怎么进到下载目录的——这条我就不展开了，说多了这篇可能就发不出来了。

## 我真正要的，其实就两件事

我把需求反复想了很久，最后缩到两件事：

一，把下载目录里乱糟糟的文件整理好，重命名成播放器认识的样子，归档进媒体库；二，给它抓上海报和简介，别让首页一整排灰图标。

于是有了 Bujic Movie。我写它时只提了一个要求：别让我配置。

下载目录一有新文件进来，它自己监听、自己识别片名和年份、自己重命名，电影按单部归、剧集按季归，顺手去 TMDB 抓海报和背景，生成 Jellyfin、Emby、Plex 都认的 NFO 文件。我在 Jellyfin 里要做的只剩一件事：点刷新。

配置文件？没有 config.yaml。最早连我自己都没适应——所有设置都在网页后台改，存进一个 SQLite 文件里，重启不丢。程序本体是单个 Go 二进制，网页前端直接嵌在里头，部署就是一段十行出头的 docker-compose。它在 Mac mini 上跑得很安静，那两块 2T 硬盘挂在下面，它也不挑。

## 真正让我烦的，是字幕

整理好了，海报也好看了，可每个晚上真正耗掉我时间的其实是字幕。

我平时美剧看得多，热门剧还好，冷门一点的中文字幕就得靠各大字幕站来回找，找着了还要核对版本号对得上对不上，下载下来经常还是繁体，还得再转一遍简体。一部片子折腾下来，一晚上就没了。

我也试过自己解决"翻译"这档子事，写过一个小工具 subx，拿 LLM 翻字幕。效果不理想，卡在两个地方：一是模型输出的字幕格式老不守规矩，时间轴说乱就乱；二是它没记忆，同一部剧里，上集一个角色名翻成 A，下集就给你翻成 B。折腾了一圈，还是老老实实回字幕站。

转机在一个看老片《冒牌天神》的晚上。那天我懒得再去找字幕了，正好订了个 agent 工具（opencode 那种命令行 agent）的套餐，就顺手让它帮我翻一下。它连上媒体库，定位到这部片，把英文字幕取走，翻译成简体中文，再放回原来的位置——Jellyfin 里直接就能选中文字幕轨了。效果比我那个 subx 强太多。

后来我想明白了差距在哪。字幕翻译这事，看着是"翻译"，干起来其实是"操作文件"：得先知道媒体库里有哪些片、字幕躺在哪个文件、翻完该放哪、文件名要守什么规矩。传统那种一次性 prompt 干不了这个，因为模型够不到你的文件系统。而现在带工具能力的 agent，能一步步调用真实接口——查列表、取字幕、传回去，每步都可编排、可复核。

那要是把这整条链路固化成标准流程，而不是每次手忙脚乱现教它一遍呢？

## 于是给它开了个 MCP

我给 Bujic Movie 加了个 MCP 端点，向 agent 开放 5 个工具：枚举媒体卡、查媒体库列表（带字幕状态）、查单部片子的字幕明细、取字幕内容、上传字幕。鉴权走独立的 API Key——agent 只能碰到你授权的目录，网页后台那套账号体系它够不着；每个 Key 能单独停用，调用记录在后台也查得到。

配套还写了一份字幕翻译 skill，把"取英文字幕 → 译成简体中文 → 放回媒体库"这条链路的每一步规范都写清楚了，别的 agent 拿过去照着就能跑，不用重新踩一遍坑。

仓库在 https://github.com/chao-eng/bujic-movie ，subx 也在上面，想看对比的可以翻翻。

这篇不是劝你也去自建。说白了，折腾这么大一圈，我最大的收获可能就是：终于不用再为一部片子的中文字幕，在字幕网站上耗掉一整个晚上了。
