## 1. 产品概述

### 1.1 背景与问题

Bujic Movie 目前只解决"文件已经在下载目录里之后"的事：监听 → 识别 → 重命名 → 归档 → 刮削 → 字幕。**"文件怎么进来"这一步完全在系统之外**。

现状与代价：

1. 找一部片要在浏览器里逐个打开站点、分别搜索、人工比对做种数与文件大小，单次 8–15 分钟（来源：2026-11 用户自述，样本 1，属产品起点假设，见 A-01）。
2. 站点越多，重复劳动越多；同一资源在不同站点重复出现，人工判断哪个能下。
3. 找到后要复制磁力、切到 qBittorrent、确认分类、贴链接，4 个以上动作，容易归错分类。
4. 下载进度只能在 qBittorrent 里看，Bujic Movie 内没有"我刚才下了什么、成没成"的视图。
5. 站点适配是长期成本：每个站点一套登录、取列表、解析字段，站点改版就失效。

现有能力对照（Prowlarr 产品形态）：

| Prowlarr 能力 | 本期是否移植 | 说明 |
|---------------|--------------|------|
| Cardigann YAML 定义加载与解释（登录、请求、解析、下载链接） | 是 | §2 用例 01~03、§3.10 需求 01~03 与 08~09 |
| 索引器统一管理（启停、优先级、测试、能力识别） | 是 | §2 用例 02~03 |
| 聚合搜索（多索引器并发、去重、分类、分页） | 是 | §2 用例 05 |
| 搜索结果推送到下载器 | 是 | §2 用例 07 |
| 下载器分类映射与优先级 | 是 | §2 用例 04、§3.10 需求 12~14 |
| 索引器限流、失败冷却、状态面板 | 是 | §2 用例 09 |
| 下载任务查看与操作 | 是 | §2 用例 08 |
| 应用同步（Radarr/Sonarr 等） | 否 | D-05 |
| Usenet 索引器与客户端 | 否 | D-03、§1.4 |
| Flaresolverr / 浏览器挑战绕过 | 否 | §1.4 |
| RSS 自动追更与定时任务 | 否 | D-05 |

### 1.2 第一性原则

本质：**把"找一部片"从多站点重复劳动，压缩成一次检索、一次点击。**

必要条件（不服务这五条的功能一律进非目标）：

1. 统一接入：不同类型站点用同一套配置与同一套查询语义被调用；新站点靠定义而不是改代码。
2. 聚合检索：一次输入并发查全部站点，结果合并成一份列表。
3. 可判读：结果带来源、大小、做种数、发布时间，能筛能排能去重。
4. 一次交接：选中结果后一次确认即交给下载器，分类自动带上。
5. 状态可见：任务是否建成、下载到哪、失败原因，在 Bujic Movie 内可查。

硬约束：

- 单二进制分发，无外部中间件（不引入 Redis/消息队列/独立守护进程）。
- 持久化只用现有 SQLite；配置沿用"默认值 / `BUJIC_` 环境变量 / `system_settings` 表"三层。
- 鉴权沿用现有 JWT 体系，不新开账号体系。
- 索引器密钥与下载器密码必须加密落库，接口不回显明文。
- 下载目录不归本模块管理：只决定"用哪个分类"，不决定"落到哪个目录"。
- YAML 定义只作为数据解析，不允许执行任意代码；模板变量只允许白名单内的占位符与过滤器。
- 所有网络请求必须有超时与并发上限，不允许无限等待。

### 1.3.1 止损与回退判据

上线后 4 周内出现任一信号，停用本模块并回到手工流程（模块可整体停用，见第 3.9 节）：

- 目标 01 的中位数耗时连续 2 周 >6 分钟。
- 目标 04 的推送成功率 <90%（排除资源已删）。
- 定义库 `full` 兼容比例 <50%，且可用通用协议实例 <3 个。
- 本模块导致既有整理/刮削失败率上升超过 1 个百分点。

停用不等于删除：配置、定义与记录保留，重新启用后继续可用。

- 定义库：从上游定义源同步、本地 YAML 导入、定义校验与版本记录、启用范围管理。
- 索引器管理：Cardigann 定义实例与通用 Torznab/Newznab 实例，启停、优先级、代理、动态设置、登录会话、测试、限流与冷却。
- 下载器管理：qBittorrent 单类型、多实例、默认实例、测试、启停、优先级、分类映射与默认分类、故障转移。
- 聚合搜索：关键词、分类、过滤、排序、去重、分页、部分失败可见。
- 推送下载（磁力/种子 → qBittorrent）、任务查看与操作、下载记录。
- 搜索历史、索引器健康面板。

不做：

| 非目标 | 理由 |

| Usenet（Newznab 索引器 + SABnzbd/NZBGet） | 用户明确不做；与 G-01 无关 |

| 移动端专属界面 | 布局随现有前端自适应，不做独立端 |

### 1.4.1 优先级与 MVP 切片

优先级口径：

- P0 必须有：去掉该需求后，"定义 → 搜索 → 推送"闭环不成立。
- P1 应该有：闭环可用但体验或可靠度明显下降。
- P2 可以有：辅助排障与效率，缺失不影响闭环。

据此 P0 为 15 条、P1 为 10 条、P2 为 2 条。P0 数量偏多的原因是本功能是一条串联链路，"能搜到"与"能交出去"各环节缺一不可；判定方法统一为"删除后闭环是否成立"，不以主观重要度排序。

MVP 切片（P0）：定义库同步与导入、定义校验、通过定义添加站点、通用协议、站点编辑与启停、测试、能力识别、登录会话、请求模板与过滤、下载器配置、分类映射、测试下载器、下载器选择、聚合搜索、部分失败可见、推送下载。

MVP 之后第一个迭代（P1）：索引器限流与冷却、结果过滤、排序、去重、分页、下载任务列表、任务操作、下载记录、下载器故障转移、验证码手动输入之外的可选增强。

第二个迭代（P2）：搜索历史、索引器状态面板。

### 管理定义库（用例 01）

### 3.9 业务规则

- BR-01：索引器地址与定义中的链接只接受 `http` 与 `https`，其它 scheme 一律拒绝。
- BR-02：索引器密钥、定义中的密码类设置、下载器密码与 API Key 均以密文落库，读接口只返回掩码（保留末 4 位）。
- BR-03：搜索只覆盖"已启用且不在冷却期"的索引器。
- BR-04：单索引器请求超时 8s；一次搜索的全量截止 15s；首屏 8s 内必须可交互。
- BR-05：分类统一映射到 Newznab 标准分类（电影 2000、剧集 5000、动画 5070）；定义未声明的分类不发起请求。
- BR-06：同一索引器连续失败 3 次进入冷却 15 分钟；任意一次成功即清零并解除冷却。
- BR-07：去重键 = 归一化标题（去标点、空格、大小写）+ 字节大小容差 2%；合并后保留做种数最高的一条，展示来源站点数与全部链接。
- BR-08：定义声明 `requestdelay` 时，取该值与全局默认间隔的较大者作为最小请求间隔。
- BR-09：同一结果指纹 60s 内重复推送返回已有任务，不重复建种。
- BR-10：定义文件只作为数据解析：不读取文件系统、不发起定义外的请求、不执行任意代码；模板变量只允许白名单占位符。
- BR-11：搜索结果不落库；只在推送下载时写一条下载记录。
- BR-12：下载记录保留 90 天；搜索历史保留最近 20 条关键词。
- BR-13：删除下载任务默认不删文件；删除文件必须在弹层中二次确认。
- BR-14：索引器状态随索引器存在，删除索引器时一并删除；下载记录保留到期满。
- BR-15：单次搜索最多返回 500 条，超出部分截断并提示。
- BR-16：索引器优先级只影响展示顺序与下载器选择，不限制并发。
- BR-17：密码、密钥、含 passkey 的完整磁力链接不得写入日志与调用记录。
- BR-18：无可用索引器时，搜索页展示配置引导，不展示空结果列表。
- BR-19：推送前必须确定分类：按分类映射推导，未命中用实例默认分类，两者皆空则不带分类提交。
- BR-20：下载器选择顺序 = 索引器单独指定的实例 > 优先级数值最小且可用的实例；同优先级按上次使用轮转。
- BR-21：本模块不向下载器传保存目录，也不创建、移动、删除下载目录；落盘位置由 qBittorrent 的实例与分类规则决定。
- BR-22：下载器连续失败 3 次标记为临时不可用 5 分钟；存在其它可用实例时自动转移，单实例时降级为可重试错误。
- BR-23：定义来源分两类：上游同步、本地导入；同名时本地导入优先，并标记为自定义。
- BR-24：停用或删除下载器不删除已在 qBittorrent 中创建的分类与标签。
- BR-25：定义解析失败必须给到"定义文件 + 顶块 + 字段"三级定位，不接受只回一句"解析失败"。
- BR-26：存储写入失败（SQLite 忙、磁盘满）时，写操作返回"保存失败，请检查磁盘空间"，不产生半条记录；定义同步整批回滚。
- BR-27：定义源返回 429 或 5xx 时最多重试 2 次，间隔 1s、2s；仍失败则本次同步作废并保留旧定义。
- BR-28：全局同时进行的搜索请求 ≤3；单次搜索最多并发查询 40 个站点，其余排队；排队站点 8s 内未被调度则本次跳过并标记排队超时。
- BR-29：同一索引器同时只允许 1 个在途请求；后续请求排队，等待超过 15s 直接跳过该站点并标记排队超时。
- BR-30：同一下载器下"来源分类"唯一；重复配置在保存时拒绝并指出冲突行。
- BR-31：下载记录写入时固化索引器名称与下载器名称；索引器或下载器被删除后，记录仍按名称可查。
- BR-32：每次搜索带请求标识；前端发起新搜索后，旧搜索的响应按标识丢弃；服务端最多保留 3 个在途搜索，超出时取消最早的。
- BR-33：只对幂等 GET 请求重试（定义清单、能力文档、种子下载），最多 2 次，退避 1s、2s；推送下载不自动重试，语义为 at-most-once。
- BR-34：定义源地址与版本可配置，默认指向 Prowlarr 官方定义源；可关闭自动同步，关闭后只使用本地定义。
- BR-35：定义同步只走 HTTPS；清单与定义文件均校验哈希，哈希不符的定义不入库并列入无效列表。
- BR-36：搜索与下载请求只能发往实例地址或定义 links 中的主机；跨主机重定向仅当目标在 links 内才跟随，否则中断并标记失败。
- BR-37：任务列表聚合全部启用实例并按实例分组；单个实例不可达只影响该组，该组保留上次快照。
- BR-38：定义缺失或标记无效时，已有实例进入只读：不参与搜索、不可修改设置，只能删除或改绑到其它定义。
- BR-39：解析与请求边界：单个定义文件 ≤2MB、YAML 嵌套 ≤10 层、单定义设置字段 ≤500、种子文件 ≤10MB、单站响应体 ≤20MB；超出即拒绝并给出原因。
- BR-40：升级只新增表与字段，不改既有表结构语义；模块可整体停用，停用后既有整理、刮削、字幕链路不受影响。
- BR-41：定义更新不自动作用于已有实例；实例使用保存时的定义快照，用户点"刷新定义"后才切换。
- BR-42：任务列表只在页面可见时轮询；标签页隐藏时停止，恢复可见时立即刷新一次。
- BR-43：允许用户导入自己浏览器中已通过验证的 Cookie 与同一 User-Agent，以复用该会话；系统不自动破解人机验证，导入失败时按"站点拒绝访问"处理。
- BR-44：中文片名在搜索前先解析为索引器实际发布的标题。解析只使用 TMDB（`/search/movie`、`/search/tv` 与 `alternative_titles`），不抓取第三方页面；解析结果按（关键词, 媒体类型）缓存，人工确认后长期复用。
- BR-45：解析失败、超时或未命中时不阻断搜索，按用户原始关键词继续，并在响应中标记 `degraded`；解析预算默认 1.5s，不得超过单次搜索的站点超时。
- BR-46：按站点 `language` 选择检索词：`zh*` 用原始中文名，`ko*`/`ja*` 优先本地文字标题，其它与未声明语言的站点优先拉丁标题；每站仍只发一次请求，不因解析增加请求数。
- BR-47：相关性判定以"该站实际收到的关键词 + 全部候选别名"为准，命中任一别名即保留该批结果，避免把英文站的正片结果当成"忽略关键词"整批丢弃。
- BR-48：网络代理是独立配置：一个地址 + 两个开关（刮削、搜索器）。TMDB 元数据与海报下载受"刮削"开关控制，索引器与定义源受"搜索器"开关控制；站点级代理优先于全局开关，下载器始终直连。

### 3.10 需求分解

#### REQ-01 定义库同步与本地导入

- 来源：R-09 / D-02 / G-06
- 优先级：P0
- 描述：支持从配置的定义源拉取定义清单与版本（地址与版本可配置，自动同步可关闭），支持导入本地 YAML 文件或目录。同步结果分新增、更新、无效、冲突四类展示；同步失败保留本地定义。
- 验收：AC-01 首次同步成功后定义库可见定义总数与最近同步时间，单条定义可查看能力与设置字段；AC-02 定义源不可达时同步返回失败原因，已有定义仍可用于新增索引器。

#### REQ-02 定义解析与校验

- 来源：R-09 / 定义安全与三级定位
- 优先级：P0
- 描述：解析 YAML 的顶块与嵌套字段，至少覆盖 id、name、description、type、language、encoding、requestdelay、links、legacylinks、followredirect、caps、login、search、download、settings。缺必填块或字段类型不符时拒绝入库并给出三级定位。
- 验收：AC-03 一份缺 `search` 块的 YAML 被标为无效，错误信息包含文件名与缺失块名；AC-04 一份含未支持块的合法 YAML 可入库并标记"部分兼容"，界面列出未支持能力。

#### REQ-03 通过定义添加索引器

- 来源：R-04 / R-09 / G-01
- 优先级：P0
- 描述：从定义库选择站点后，按定义的 settings 动态生成表单（文本、密码、复选框、下拉、说明），并补名称、代理、优先级、启用、绑定下载器。密码类字段掩码存储。
- 验收：AC-05 选择定义后表单字段与 YAML 声明一致，必填校验就位，保存后列表状态为"未测试"；AC-06 密码类设置保存后读接口为掩码，编辑时不回填明文。

#### REQ-04 通用 Torznab/Newznab 索引器

- 来源：R-01 / D-01 / G-01
- 优先级：P1
- 描述：保留通用协议入口：手动填名称、接口地址、API Key、分类映射、代理、优先级。用于未被定义库覆盖的站点与其聚合网关。
- 验收：AC-07 通用入口保存后 10s 内可完成一次成功测试，能力文档中的分类数与站点一致。

#### REQ-05 编辑、启停与删除索引器

- 来源：R-04 / G-01
- 优先级：P0
- 描述：支持编辑全部实例字段、启用/停用、删除，以及为单实例绑定优先使用的下载器。删除需二次确认。
- 验收：AC-08 停用后下一次搜索不再包含该站点，重新启用后下一次搜索包含；AC-09 删除确认后列表移除，其历史下载记录仍可按站点名查询。

#### REQ-06 测试索引器连通性

- 来源：R-04 / R-09 / G-05
- 优先级：P0
- 描述：按定义执行登录（如需）与一次探测请求，返回站点名称、协议、支持分类数、10000ms 内的探测耗时、登录状态；失败分类为认证失败、不可达、超时、解析失败、需验证码。
- 验收：AC-10 测试 10s 内返回，成功含 5 项信息，失败含原因类别与首个不匹配字段；AC-11 验证码弹层输入正确后 10 分钟内再次测试无需重复输入。

#### REQ-07 能力识别与查询降级

- 来源：R-05 / R-09 / G-02
- 优先级：P0
- 描述：从定义 caps 读取支持的搜索模式、分类映射与条数上限。站点不支持结构化影视搜索时退回关键词查询，并在结果页标注。
- 验收：AC-12 对只声明 `search` 模式的站点发起影视搜索时，实际请求使用关键词参数且返回结果，页面标注"仅关键词搜索"。

#### REQ-08 登录与会话维持

- 来源：R-09 / D-09 / G-01
- 优先级：P0
- 描述：按定义 login 块执行 form、get、post 三类登录，保存 Cookie 与会话状态；会话过期或站点返回未登录特征时自动重登一次。验证码场景要求用户输入，不自动识别。
- 验收：AC-13 需要登录的站点保存后首次测试弹出验证码输入，成功后会话状态为"已登录"，后续搜索不再要求输入；AC-14 会话过期后首次搜索自动重登并成功返回结果。

#### REQ-09 请求模板与过滤链执行

- 来源：R-09 / G-01
- 优先级：P0
- 描述：按定义执行 search.path 与 search.paths、inputs、headers、keywordsfilters、preprocessingfilters、rows、fields，以及 download 块的下载链接与 infohash 提取。支持过滤器：querystring、timeparse、dateparse、regexp、re_replace、split、replace、trim、prepend、append、tolower、toupper、base64decode、base64encode、urldecode、urlencode、htmldecode、htmlencode、timeago、reltime、fuzzytime、validfilename、diacritics、jsonjoinarray、hexdump、strdump、validate、and、or、eq、ne、has、not、contains。
- 验收：AC-15 单个定义的多条 search path 按分类分别执行并合并结果；AC-16 未知过滤器名不导致搜索崩溃，该站点标记"部分兼容"并在结果页提示。

#### REQ-10 索引器限流与失败冷却

- 来源：R-04 / G-05
- 优先级：P1
- 描述：每个索引器有最小请求间隔（默认 2s，定义声明时取较大值），并发搜索时排队；连续失败 3 次进入 15 分钟冷却，冷却期内不发起请求。
- 验收：AC-17 同一站点相邻两次请求间隔不小于配置值；AC-18 连续失败 3 次后状态变"冷却中"，冷却期内搜索跳过并展示剩余时间，成功一次后立即恢复。

#### REQ-11 配置 qBittorrent 下载器

- 来源：R-03 / R-08 / D-03 / G-04
- 优先级：P0
- 描述：按 Prowlarr 提供者模型新增、编辑、删除 qBittorrent 实例。基础字段为名称、地址、端口、启用、优先级、默认实例；连接字段为 SSL、URL Base、API Key 或账号密码（二选一）；任务字段为默认分类、初始状态（开始 / 暂停 / 强制开始）、顺序下载、首尾优先、内容布局。
- 验收：AC-19 仅填地址与端口即可保存，其余字段取默认值，列表状态为"未测试"；AC-20 保存后读接口的密码与 API Key 均为掩码，编辑时不回填明文。

#### REQ-12 分类映射

- 来源：R-08 / G-04
- 优先级：P0
- 描述：每个下载器可配置多条映射：一条来源分类（Newznab 分类或分类组）对应一个下载器分类。推送时先精确匹配，再父类匹配，最后回落到默认分类。
- 验收：AC-21 配置"剧集 5000 → tv"后，剧集结果推送带分类 tv；配置"2040 → 4k"时 2040 精确命中优先于 2000 的映射；未命中且无默认分类时不带分类提交。

#### REQ-13 测试下载器连通性

- 来源：R-03 / R-08 / G-04
- 优先级：P0
- 描述：测试时完成认证并读取版本、默认分类与全部分类映射对应的分类；分类不存在时自动创建；区分认证失败、不可达、分类创建失败。
- 验收：AC-22 测试 10s 内返回，成功展示版本号与逐条分类状态，认证失败展示"账号或密码错误"，分类创建失败列出来源分类与原因。

#### REQ-14 下载器选择、索引器绑定与故障转移

- 来源：R-03 / R-08 / G-04
- 优先级：P0
- 描述：多实例时优先使用索引器单独指定的实例；否则按优先级选择可用实例，同优先级轮转。下载器连续失败进入临时不可用并自动转移。
- 验收：AC-23 两个实例时停用高优先级实例，推送落到下一个可用实例且记录体现实际实例；AC-24 索引器绑定的实例连续失败 3 次后，推送自动转移到其它可用实例并提示。

#### REQ-15 聚合搜索

- 来源：R-05 / G-02
- 优先级：P0
- 描述：输入关键词后并发查询全部可用索引器，结果边到边渲染；页面 2s 内可交互，任何已返回站点的结果立即展示，全部完成或到达截止时间后给出最终列表。
- 验收：AC-25 5 个启用站点时页面 2s 内可交互，已返回站点的结果立即出现，8s 内展示已返回的全部结果，15s 内给出最终列表；AC-26 空关键词时按各站最新发布返回，每站最多 50 条。

#### REQ-16 分类筛选

- 来源：R-05 / G-03
- 优先级：P1
- 描述：可按电影、剧集、动画、其它筛选；请求阶段只向声明支持该分类的站点发起查询。
- 验收：AC-27 选"电影"时不支持电影分类的站点不被请求，页面不报错且结果仅含该分类。

#### REQ-17 结果过滤

- 来源：R-05 / G-03
- 优先级：P1
- 描述：支持按大小区间、发布时间区间、最小做种数过滤；过滤在已取回结果上即时生效，不重新请求站点。
- 验收：AC-28 任一条件变更后列表 200ms 内更新，且没有新增站点请求。

#### REQ-18 结果排序

- 来源：R-05 / G-03
- 优先级：P1
- 描述：支持按做种数、大小、发布时间、来源站点排序，默认做种数降序；缺做种数的结果排在后面。
- 验收：AC-29 切换排序 200ms 内完成，默认顺序与"做种数降序"一致。

#### REQ-19 跨站去重

- 来源：R-05 / G-03
- 优先级：P1
- 描述：归一化标题相同且大小差在 2% 以内的结果合并为一条，展示来源站点数与可切换的链接。
- 验收：AC-30 同一资源来自 3 个站点时列表只出现 1 条，标注"3 个来源"，展开可见 3 个链接。

#### REQ-20 部分失败可见

- 来源：R-05 / G-02
- 优先级：P0
- 描述：任一站点超时、限流、需重新登录或解析失败时，其余结果正常展示，并提供"n 个站点失败"入口查看站点名与原因。
- 验收：AC-31 1 个站点解析失败、2 个成功时列表展示成功结果，顶部提示"1 个站点失败"，展开含站点名与原因类别。

#### REQ-21 结果分页

- 来源：R-05 / G-02
- 优先级：P1
- 描述：每页 50 条，滚动加载更多；单次搜索上限 500 条。
- 验收：AC-32 滚动到底部加载下一页且总数正确，达到 500 条时提示缩小关键词。

#### REQ-22 推送下载

- 来源：R-06 / G-04
- 优先级：P0
- 描述：把选中结果的磁力或种子交给 qBittorrent，携带按映射推导的分类；提交前展示分类并允许改一次。
- 验收：AC-33 点击确认后 15s 内返回"任务已创建"，下载器中可见该任务；AC-34 同一结果 60s 内再次推送返回"已存在"并给出已有任务，下载器任务数不增加；AC-35 弹层展示的分类与实际提交分类一致。

- 来源：R-03 / G-04

- 描述：每 5s 从下载器拉取任务，展示名称、大小、进度、速度、状态、ETA；按状态与时间排序。
- 验收：AC-36 多个实例时任务按实例分组，进度在 6s 内反映下载器变化；AC-37 某实例不可达时仅该组保留上次数据并标注数据时间。

- 来源：R-03 / G-04

- 验收：AC-38 暂停与继续在 3s 内于下载器生效并在列表体现；AC-39 未勾选"同时删除文件"时文件仍在磁盘，勾选后需二次确认才执行。

- 来源：R-06 / G-04

- 描述：每次推送写入一条记录，含结果名称、索引器、下载器、大小、状态、错误类别、时间；失败也记录。
- 验收：AC-40 成功与失败各产生 1 条记录且错误类别非空，记录可按索引器与时间筛选，保留 90 天；索引器删除后仍按名称快照可查。

#### REQ-26 搜索历史

- 来源：R-05 / G-01
- 优先级：P2
- 描述：保留最近 20 条关键词，支持点击复用、单条删除与清空。
- 验收：AC-41 连续搜索 21 个不同关键词后仅保留最近 20 条，点击任一历史可重新发起搜索。

#### REQ-28 导入浏览器会话（应对人机验证）

- 来源：R-10 / G-01 / D-09
- 优先级：P1
- 描述：索引器可保存用户导入的 Cookie 与 User-Agent，并用于该站点的全部请求。导入入口有两处：站点编辑表单，以及供浏览器扩展调用的接口（按站点域名匹配实例，域名对应多个实例时返回候选）。Cookie 值只写不读，读接口只返回 Cookie 名称。
- 验收：AC-44 导入后读接口只显示 Cookie 名称（如 cf_clearance）而不显示值，User-Agent 完整可见；AC-45 同一域名匹配多个站点时返回候选列表不落库，缺少 User-Agent 或 Cookie 时返回参数错误。

#### REQ-27 索引器状态面板

- 来源：R-04 / G-05
- 优先级：P2
- 描述：展示每站最近成功时间、连续失败数、近 20 次平均耗时、冷却剩余时间、登录会话状态，每 30s 刷新。
- 验收：AC-42 面板 30s 内自动刷新且 5 项数据与状态表一致；AC-43 冷却中或需重新登录的站点在搜索页与面板同时标注。

#### REQ-29 中文片名解析与人工确认

- 来源：R-04 / 白名单位置的片名差异
- 优先级：P1
- 描述：搜索前用 TMDB 把中文片名解析为官方原名与各地别名，按站点语言选择检索词；搜索页展示候选列表供人工确认，确认后用于后续搜索并长期复用；可清除已确认的选择，也可强制重新识别。
- 验收：AC-46 输入中文片名搜索，英文站收到的关键词为拉丁原名，中文站仍收原始中文名；AC-47 候选列表包含海报、年份、原名与别名，点选后重新搜索且后续同一关键词不再请求 TMDB；AC-48 TMDB 不可用时搜索照常返回结果，界面标注"按原词搜索"。

#### REQ-30 独立网络代理

- 来源：R-04 / 部署环境差异
- 优先级：P1
- 描述：设置页提供统一的代理地址与两个独立开关，分别控制刮削（TMDB 元数据与图片）与搜索器（定义源与站点请求）。改动保存即生效，无需重启。
- 验收：AC-49 只开"搜索器"开关时，站点搜索经过代理而 TMDB 直连；只开"刮削"开关时相反；AC-50 清空代理后两条链路都回到直连，站点级代理覆盖仍然有效。

```text
  │◄────────────│◄───────────────────│  写下载记录           │                     │
```

超时约定：单站 8s、全量 15s；超时站点不等待，直接标记失败。

### 4.2 定义加载流程

```text
[定义源] ──拉取清单──► [版本比较] ──新增/更新──► [YAML 解析] ──校验通过──► [定义库]
                                                        │
                                                        └──校验失败──► [无效列表（附三级定位）]

[本地 YAML 导入] ──────────────────────────────────────► [YAML 解析]
                                                        └── 同名覆盖 ──► 标记"自定义"
```

- 解析只读 YAML 数据，不执行任何脚本与外部命令（定义安全约束）。
- 定义版本变低时不覆盖本地，除非用户手动选择。
- 单条定义失败不影响整批入库。

### 4.3 索引器登录与会话状态

```text
[无会话] ──需要登录──► [待验证] ──表单登录成功──► [已登录]
    │                      │                        │
    │ 无需登录             │ 需要验证码              │ 会话过期/返回未登录
    ▼                      ▼                        ▼
[已登录]              [等待用户输入] ──输入成功──► [待验证]
                                                       │
                                                       └──失败 3 次──► [登录失败（需人工处理）]
```

- 会话以站点为单位保存 Cookie 与过期时间，不跨站点复用。
- 等待验证码超过 10 分钟作废，不阻塞其它站点搜索。

### 4.4 下载任务状态机

```text
[待提交] ──提交成功──► [下载中] ──完成──► [已完成] ──► [做种中]（下载器报告）
    │                     │  ▲
    │提交失败              │  └──继续──┐
    ▼                     ▼           │
[失败]                [已暂停] ────────┘
                          │
                          └──删除──► [已删除]（终态）
```

规则：

- 状态以下载器为准，本地只做展示缓存，不产生第二套状态源。
- 下载器不可达时不伪造状态迁移，保留上次快照并标注时间。
- "已删除"为终态；再次推送同一结果按重复推送规则处理。
- 提交结果未知（超时）记为「结果未知」（pending），由任务列表下一次刷新对齐。

### 4.5 索引器状态机

```text
[未测试] ──测试成功──► [可用] ──连续失败 1~2 次──► [可用(降级)] ──第 3 次失败──► [冷却中]
                          ▲                                                        │
                          └──────────────── 冷却到期 或 手动恢复 ───────────────────┘
[未测试] ──测试失败──► [不可用] ──测试成功──► [可用]
```

- 冷却中的站点不参与搜索，不阻塞其他站点。
- 手动"立即恢复"只解除冷却，不改历史失败计数，直到下一次成功才清零。

### 4.6 中断与恢复

- 页面刷新：搜索结果不恢复（结果不落库），回到初始态；下载任务从下载器实时拉取。
- 服务重启：定义库、索引器状态、下载记录、搜索历史从 SQLite 恢复；无内存中队列需要重放。
- 定义同步中断：保留上一版定义可用，下次同步整批重来。
- 下载器重启：任务列表下一次拉取自动对齐，不视为错误。

### 4.7 定义生命周期

```text
[新增] ──校验通过──► [可用] ──上游下架──► [缺失] ──重新同步──► [可用]
   │                    │  ▲
   │校验失败             │  └──用户刷新定义──┐
   ▼                    ▼                    │
[无效]              [只读] ──────────────────┘
```

- 定义"缺失"或"无效"时，引用它的实例进入只读（见第 3.9 节只读规则），不参与搜索。
- 定义更新只影响之后新建的实例；已有实例使用保存时的定义快照。
- 删除定义不删除实例，实例保留以便用户改绑或删除。

### 4.8 下载器可用性

```text
[可用] ──连续失败 3 次──► [临时不可用(5 分钟)] ──到期──► [可用]
   ▲                              │
   └──────── 任意一次成功 ─────────┘
```

- 临时不可用期间，推送按优先级转移到其它可用实例；单实例时返回可重试错误。
- 该状态只影响推送，不影响任务列表读取；任务列表按实例分别降级。

## 6. 非功能需求

### NFR-01 功能适合性

- 目标：搜索结果与关键词相关；分类映射正确率 ≥95%；上游定义中 `full` 兼容比例 ≥80%。
- 口径：抽样 200 次搜索人工判定前 20 条相关性；抽样 200 条分类人工核对；统计定义库兼容状态分布。
- 验证：上线后 4 周抽样审计，记录于测试状态文件。

### NFR-02 性能效率

- 目标：5 个站点时首屏 P95 ≤8s；单站请求超时 8s；搜索全量截止 15s；结果过滤与排序在 200ms 内。
- 口径：服务端按索引器数量分桶统计搜索耗时（按 ≤1000ms、≤8000ms、>8000ms 分桶）；前端记录交互到列表更新耗时。
- 资源上限：单次搜索内存增量 ≤150MB，进程常驻内存增量 ≤200MB。
- 验证：本地压测（10 并发 × 5 站点 × 各 50 条模拟结果）+ 线上耗时直方图监控 + 内存采样。

### NFR-03 性能效率（容量）

- 目标：支持 1000 条定义、50 个索引器、单日 500 次搜索；下载记录 10 万条时列表查询 P95 ≤300ms。
- 口径：1000 条定义的加载耗时、SQLite 数据量与查询耗时。
- 验证：造数压测（1000 条定义、10 万条记录）测量加载与列表查询耗时。

### NFR-04 兼容性

- 目标：qBittorrent Web API 4.6 与 5.x 均可登录并推送；Torznab 1.0 与 Newznab 0.9 能力文档均可解析；Prowlarr 定义 v11 与 v12 的 YAML 均能加载；Chrome、Edge、Safari 最近两个大版本可用。
- 口径：人工在 4.6 / 5.x 各跑一次完整链路；两版定义各取 20 份跑解析与搜索；三浏览器各跑一次搜索与推送。
- 验证：兼容性测试清单逐项签字（第 4 阶段执行）。

### NFR-05 交互能力

- 目标：从空库到首次搜索成功 ≤5 步（同步定义、添加站点、添加下载器、输入搜索、点击下载），首次完成 ≤10 分钟；任务完成率 ≥90%；求助率 ≤10%；错误提示必含下一步动作；全部操作可键盘完成；文本对比度 ≥4.5:1。
- 口径：新用户任务走查计时与操作计数；对比度用工具测量。
- 验证：可用性走查 5 次，记录步数与卡点；无障碍扫描零严重项。

### NFR-06 可靠性

- 目标：单站点故障不导致搜索失败（部分失败可见）；自然月可用性 ≥99.5%（排除计划维护 ≤30 分钟）；自身原因导致的搜索失败率 ≤1%；服务重启后配置、定义、记录零丢失；推送不产生重复任务。
- 告警：连续 3 次搜索失败率 >50% 或定义同步连续失败 2 次时，在页面顶部提示并写入日志。
- 口径：失败请求数与原因分类；重启前后记录条数比对；重复任务按指纹统计。
- 验证：故障注入（断网、站点 429、下载器停机、定义源 500）+ 重启演练，结果记入测试状态文件。

### NFR-07 安全性（安保）

- 目标：密钥、密码、代理凭据、会话凭据、定义中密码类字段均加密存储；接口不回显明文；未登录访问一律 401；日志与下载记录不含完整磁力与 passkey；索引器地址仅允许 http/https；定义同步走 HTTPS 并校验哈希；YAML 不可读文件系统或执行命令。
- 口径：代码审计 + 抓包与日志抽查 + 越权用例 + 恶意 YAML 用例。
- 验证：安全用例逐条执行（未登录、掩码、日志脱敏、非法 scheme、路径穿越型 YAML、重复提交）。

### NFR-08 可维护性

- 目标：新增一种连接方式只改适配层，不改搜索与下载主流程；定义解析错误可按文件与字段定位；关键链路日志含索引器标识与搜索标识；配置变更 5s 内生效，无需重启。
- 口径：代码评审检查耦合点；错误日志抽样；配置修改后计时验证生效。
- 验证：以"新增一份 YAML 定义并跑通搜索"为演练任务，记录改动文件数与生效耗时（目标 ≤5s）。

### NFR-09 灵活性

- 目标：新增定义无需发版；索引器类型扩展不改数据库主表结构；下载器实例可水平增加（≥5 个）；升级不丢配置、定义与记录。
- 口径：导入一份新定义到可用搜索的耗时（目标 ≤2 分钟）；迁移脚本执行结果；多实例推送正确率。
- 验证：导入演练（≤2 分钟可用）+ 从上一版本数据升级演练 + 5 实例推送测试。

### NFR-10 安全性（功能安全）

- 目标：误操作不可逆风险受控——删除任务默认不删文件；删除文件需二次确认；推送前展示实际分类；重复推送不重复建种；不兼容定义不可被实例化。
- 口径：上述五项在验收用例中的通过率 100%。
- 验证：按用例 02、07、08 的备选流逐条演练，记录结果。

### NFR-11 可观测性

- 目标：每次搜索产生一条结构化日志（索引器数、成功数、失败数、耗时毫秒值），日志保留 90 天；定义同步产生一条汇总日志（新增、更新、无效、冲突）；面板数据与日志可对账。
- 口径：日志字段完整率 100%；面板与日志抽样 20 次一致。
- 埋点：`search_submit`、`search_first_render`、`grab_confirm`、`grab_result` 四个前端事件，字段含索引器数、耗时与结果状态；口径与目标 01 一致。
- 验证：日志抽样核对 + 面板对账 + 埋点事件字段核对。

### NFR-12 运维与部署

- 目标：不新增进程与端口；二进制体积增量 ≤8MB；启动时间增量 ≤300ms；数据库与定义缓存合计增长 ≤1GB/年。
- 口径：构建产物对比、启动耗时增量（目标 ≤300ms）、数据目录体积。
- 验证：构建与启动基准测试，与当前版本对比。

## 8. 易用性设计原则

- 首次价值路径：同步定义库（1）→ 添加站点（2）→ 添加下载器（3）→ 搜索并推送（4），共 4 步、≤10 分钟；其余字段折叠在高级设置。该路径比通用产品多一步，原因是必须先接上两个外部系统，属本功能域的例外。
- 术语人话：界面用"站点""下载器""分类"，不出现 indexer、cardigann、torznab、info hash 等词；技术名词只在高级设置与定义详情内出现。
- 空态即引导：无定义、无站点、无下载器、无结果四种空态都给下一步按钮，不出现纯空白。
- 不阻塞：搜索边到边渲染，任一站点慢不拖住整页；定义同步期间旧定义继续可用。
- 破坏性操作默认安全：删除任务默认保留文件；删除站点/下载器需确认；不兼容定义不可实例化。
- 状态不只靠颜色：可用/冷却/需登录/失败同时用文案与图标表达。

### 9.2 假设与验证方式

- A-01：目标用户以中文影视为主，定义库可直接覆盖常用站点。验证：上线 4 周统计各定义的实际使用与成功搜索占比。
- A-02：qBittorrent 与 Bujic Movie 同内网，单次调用延迟 ≤50ms。验证：测试连接页记录耗时，超阈值时提示网络位置。
- A-03：用户可自行取得站点账号或 API Key。验证：配置完成率（保存后 24h 内测试通过的比例）。
- A-04：上游定义源可访问，且版本号单调递增。验证：同步日志的成功率与版本分布；失败率超过 5% 时提示配置代理。
- A-05：多数定义不依赖 Flaresolverr 与自动验证码。验证：定义库兼容状态分布，`partial` 占比超过 40% 时评估补充能力。

### 9.3 风险

| ID | 风险 | 影响 | 缓解 |
|----|------|------|------|
| RISK-01 | 上游定义改版或站点改版 | 定义不可用或解析失败 | 三级错误定位、同步可回退、通用协议兜底、定义库展示兼容状态 |
| RISK-02 | 定义文件许可约束 | 分发合规问题 | 不随包分发，仅运行时同步或本地导入（D-02） |
| RISK-03 | 恶意或畸形 YAML | 资源耗尽或越权访问 | 只做数据解析、白名单过滤器、限制嵌套深度与文件大小、禁止外部引用 |
| RISK-04 | 私站限流或封禁 | 搜索结果缺失 | 请求间隔取定义值与默认值的较大者、冷却机制、状态面板可见 |
| RISK-05 | 磁力链接含私站 passkey 泄露 | 账号风险 | 不落库、不写日志、界面不展示完整链接 |
| RISK-06 | 资源已删除导致推送失败 | 下载失败 | 记录错误类别，提示换源 |
| RISK-07 | qBittorrent 分类目录规则配错 | 文件落到意外位置 | 推送前展示分类；文档说明目录归属下载器；记录实际分类 |
| RISK-08 | 站点条款或内容合规风险 | 账号被封或法律责任 | 只使用用户自有账号与站点授权；不托管内容、不绕过访问控制；使用说明中提示遵守站点条款 |

合规声明：本模块只做索引查询与下载指令转发，不存储、不传播媒体内容；站点账号、邀请与下载权限由使用者自行取得并遵守站点条款。
