### 1.2 设计约束（来自 PRD 与现有工程）

- 单二进制、无新端口、无外部中间件；只用现有 SQLite（`glebarez/sqlite`，纯 Go）。
- 分层沿用 `Controller → Service → Repository`；装配仍集中在 `internal/router/router.go`。
- 迁移沿用各仓储构造器 `AutoMigrate`，本模块只新增表，不改既有表（BR-40）。
- 鉴权沿用 JWT（`middleware.AuthRequired`），不新增账号体系。
- 凭据 AES-GCM 加密，密钥由 `server.secret_key` 派生。
- 前端唯一入口为 `/api/v1`，响应沿用 `pkg/response` 的 `{code,msg,data}` 信封。

### 1.3 与既有链路的边界（明确禁止）

| 边界 | 约束 |
|------|------|
| watcher / transfer | 本模块不写媒体卡目录、不触发整理、不读 `media_cards` |
| scrape / nfo | 不调用 TMDB、不生成 NFO |
| subtitle / MCP | 不注册 MCP 工具、不读写字幕目录 |
| 配置 | 只在 `config.Config` 增 `Search` 段；不新增 config.yaml |

### 3.1 代理解析顺序

出口分成两条独立链路，共用一个代理地址：

1. **搜索器**：站点级 `proxy_url`（加密存储，站点页可改）→ `network.search_via_proxy` 开启时的 `network.proxy` → 直连。
2. **刮削**：`network.scrape_via_proxy` 开启时的 `network.proxy` → 直连。TMDB API 与 `image.tmdb.org` 图片下载都走这条链路。

`search.proxy` 保留为升级兼容：`network.proxy` 为空时回退读取它，所以老配置不会失效。`network.proxy` 通过 resolver 每次出站读取，保存即生效。

下载器（CMP-10）标记 `BypassProxy`，始终直连，避免内网下载器被绕进公网代理。定义同步与站点请求共用同一解析顺序。

定义同步只下载一个 `package.zip`（约 1.2MB）后离线解压解析；单文件历史路径 `/{id}`（无 `.yml` 后缀）仅作兜底。代理自检只请求定义清单，不触发全量同步，因此能在数秒内返回。

### 4.2 依赖方向（禁止反向）

```text
controller ──► service ──► repository ──► gorm/SQLite
                   │
                   ├──► connector（接口）
                   │        ├── torznab
                   │        └── cardigann ──► definitionparser

                   ├──► qbittorrent
```

- `service` 不 import `controller`；`connector` 不 import `repository`。
- `cardigann` 包不得引用 `qbittorrent`、`transfer`、`watcher`。
- 所有外部 I/O 经过 CMP-06 或 CMP-10，便于打桩。

### 5.3 并发模型

```text
[HTTP handler goroutine]
        │ 创建 searchCtx(deadline 15s) + search_id
        ▼
[全局搜索信号量 cap=3] ──排队（无超时，由 15s ctx 兜底）
        ▼
[站点 worker pool cap=min(20, N)] ──每站一个 goroutine
        │                                   │
        │                                   └─► [站点信号量 cap=1] ──► [rate.Limiter]
        ▼
[结果 channel cap=20] ──► [聚合 goroutine] ──► 去重/排序 ──► 响应
```

约束（与 BR 对齐）：

| 约束 | 实现 | 出处 |
|------|------|------|
| 全局并发搜索 ≤3 | 带缓冲 channel 作为信号量；拿不到令牌的请求阻塞，受 15s ctx 约束 | BR-28 |
| 单次站点并发 ≤20 | worker pool 上限；站点按优先级排序入队 | BR-28 |
| 排队 8s 未调度则跳过 | 每站带 `enqueueAt`，出队时校验；超时写"排队超时"失败项 | BR-28 |
| 同站单在途 | 每个索引器一个带缓冲 1 的 channel | BR-29 |
| 同站排队 >15s 跳过 | 站点信号量等待用 15s 子 ctx；超时写"排队超时" | BR-29 |
| 单站预算 8s | `context.WithTimeout(parent, 8s)`；多 search path 共享该预算，单 path 超时 = max(2s, 8s/path 数) | BR-04 |
| 全量截止 15s | searchCtx 截止；到点取消剩余请求，返回已得结果 | BR-04 |
| 旧响应丢弃 | 请求携带 `request_id`；前端比对，不符丢弃 | BR-32 |
| 在途搜索 ≤3 | 全局信号量即上限；排队请求不创建 goroutine | BR-32 |
| 结果 channel 满 | 聚合端持续消费；单站最多产出 1 个批次，不会阻塞超过 1s | — |
| 轮询节流 | 前端 `document.visibilityState` 控制；隐藏停、恢复立即刷一次 | BR-42 |

**写入串行化**

- SQLite 单写者：所有写操作短事务（<50ms），不在事务内做网络 I/O。
- 索引器状态更新（成功/失败/冷却）用单条 UPSERT；高频搜索下最多每站每秒 1 次。
- 定义同步用进程内 `sync.Mutex` 单飞；同步期间搜索读旧快照。

### 5.4 降级与恢复

| 场景 | 检测 | 降级 | 恢复 |
|------|------|------|------|
| 单站超时/解析失败 | 8s ctx / 解析错误 | 部分结果 + 失败清单 | 下次搜索重试；连续 3 次进冷却 |
| 定义源不可达 | 同步错误 / 429 / 5xx | 使用本地定义 | 手动或下次启动同步 |
| 定义被下架 | 同步清单缺失 | 实例只读、不参与搜索 | 用户改绑或定义恢复 |
| 下载器不可达 | 连接错误 / 5xx | 转移其它实例；任务分组降级 | 5 分钟后自动恢复探测 |
| 推送结果未知 | 15s 超时 | 记 pending，提示到任务页确认 | 任务列表下一次刷新对齐 |
| SQLite 忙/磁盘满 | 写错误 | 返回 50001，任务不落记录 | 释放空间后重试 |
| 进程重启 | 启动加载 | 无内存队列需重放；会话/状态从 DB 恢复 | 自动 |

| 启动顺序 | `LoadConfig → DB → repositories.AutoMigrate → services → controllers → router`（沿用现有顺序） |
| 关闭模块 | `search.enabled=false`：模块路由返回 404（`/search/status` 例外，返回 `{enabled:false}`），侧栏隐藏入口；无后台任务需要停止 |
| 灰度 | 单实例部署，无灰度；以模块开关作为回退粒度 |
| 回滚 | 降级二进制即可；新增表保留不删，旧版本不读取；无破坏性迁移 |
| 数据备份 | 仍只需备份 SQLite 文件；定义原文在库内，随备份走 |

资源预算：

| 项 | 预算 | 说明 |
|----|------|------|
| 常驻内存增量 | ≤200MB | 定义缓存（LRU 256 条）+ 会话缓存 |
| 单次搜索峰值 | ≤150MB | 500 条 × 约 2KB + 解析中间态 |
| 磁盘 | ≤1GB/年 | 定义约 10MB + 记录 10 万条约 100MB + 索引 |
| CPU | 搜索解析为突发型 | 单次 ≤200ms CPU；无常驻轮询 |

### 7.3 迁移与清理

- 全部表由各自仓储构造器 `AutoMigrate`；无 ALTER 既有表。
- 清理任务：搜索时顺带清理，不引入定时器：
  - `download_records` 删除 `created_at < now-90d`（每次推送后最多跑一次，10 分钟内去重）。
  - `search_history` 保留 `last_used_at` 最新 20 条。
  - `indexer_sessions` 过期 24h 删除。
  - `search_title_aliases` 删除 `updated_at < now-30d`；用户手动清除立即删除。
- 删除索引器：事务内删 `indexers`、`indexer_sessions`、`indexer_status`；`download_records` 保留（快照可查）。
- 删除下载器：事务内删 `download_clients`、`download_client_categories`；索引器的 `download_client_id` 置 0。

### 8.3.1 分类解析的对外呈现

推送前的确认弹层不再让用户“留空猜一次”：`API-29` 返回将使用的下载器、分类、命中规则（`mapping` / `parent` / `default` / `none`）与本下载器可选的分类列表。弹层默认填入该结果，用户可改。命中 `default` 时提示“使用了默认分类”，命中 `none` 时提示“将由下载器决定”。

可选分类的来源是 `API-28`（下载器实际已有的分类），下载器不可达时退化为“分类映射里配置过的目标名”，保证弹层始终有可选项。

## 10. 风险与 Spike 结论

| ID | 风险 | 触发条件 | 影响 | 缓解 | 状态 |
|----|------|----------|------|------|------|
| RISK-09 | Cardigann 解释覆盖不足 | S-01/S-02 未达判定标准 | 大量定义标 partial | 回退通用协议 + 逐站适配器 | 未关闭，实现前验证 |
| RISK-10 | 解析性能超预算 | 单定义解析 P95 >300ms | 首屏超 2s | 定义解析结果缓存 + 并发上限 | 设计中缓解 |
| RISK-11 | SQLite 写争用 | 并发搜索 + 状态更新 | 写超时 | 短事务、UPSERT、每分钟合并状态写入 | 设计中缓解 |
| RISK-12 | 代理不可达或认证失败 | 站点经代理 | 该站全失败 | 按站标记；测试接口区分代理错误 | 设计中缓解 |
| RISK-13 | 密钥轮换导致历史密文不可解 | `server.secret_key` 变更 | 凭据需重录 | 解密失败清空并提示重录，不阻塞启动 | 设计中缓解 |
| RISK-14 | 前端 5s 轮询叠加多标签页 | 多标签打开任务页 | 请求量线性上升 | 可见性停轮询 + 单页请求合并 | 设计中缓解 |

**Spike 结论**（2026-11-20 实现后回填）：

- S-01 通过：真实定义抽样 96 份，96 份可解析（85 full / 11 partial / 0 invalid）。
- S-02 部分通过：字段提取的单测与桩站点通过；真实站点字段正确率尚未抽检，保留为 RISK-09。
- S-03 通过（桩）：表单登录、Cookie 会话、Cookie 方式登录、验证码拒绝路径均有测试。
- S-04 部分通过：qB 5.x 端到端通过；4.6 未实测。
