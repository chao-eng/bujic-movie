## 3.1 真实定义抽样（S-01 / S-02）

样本：Prowlarr 官方定义库 v11 随机抽 100 份，成功下载 96 份（4 份下载失败）。
工具：`go run ./cmd/defcheck <目录>`。

| 结果 | 数量 | 占比 |
|------|------|------|
| 完全兼容（full） | 85 | 88.5% |
| 部分兼容（partial） | 11 | 11.5% |
| 不可用（invalid） | 0 | 0% |

partial 原因分布：`replaces` 9 份（Prowlarr 自身也未实现该遗留字段）、`certificates` 2 份（自定义 CA，本期不支持）。

结论：S-01（YAML 解析）通过；S-02 只验证了"定义可解析"，字段提取正确率仍需真实站点抽样，记为未关闭风险。
过程中修复的真实兼容问题：字段过滤器中的字面量块解析、`requestDelay` 驼峰键、仅 `infohash` 或 `magnet` 字段的结果、`cookie` 登录方式、Java 风格日期格式。

### 新增原生连接器

Knaben 与 SubsPlease 在 Prowlarr 中是 C# 原生实现，不提供 YAML 定义：

- **Knaben**：`POST https://api.knaben.org/v1`，JSON 请求体（`order_by/from/size/search_type/query/categories`），响应 `hits[]`。实现 `internal/service/connector/knaben.go`，含 Newznab ↔ Knaben 分类双向映射。
- **SubsPlease**：`GET https://subsplease.org/api/?f=search|latest&tz=UTC`，响应是以剧名为 key 的嵌套对象，每个条目含多个分辨率的 magnet。实现 `internal/service/connector/subsplease.go`，从 magnet 的 `xl` 参数取真实大小，缺失时按分辨率估算。

两者均实现 `Connector` 接口（Test/Search/ResolveDownload/SupportsCategories），前端「类型」下拉新增两个选项，无需导入 YAML。

相关率口径：Top20 标题包含关键词或其常见中文别名即算相关。

修复后 U3C3 的无关批次被整批丢弃，并作为 `irrelevant` 失败项展示；Oppenheimer 的总数从 63 降到 3，正是被污染的部分。

**发现的问题**：

- U3C3 返回与关键词无关的内容（例：搜 Oppenheimer 的前 17 条均为无关资源）。其定义依赖站点的 `search2` 令牌，YAML 里是硬编码值，已失效；站点忽略关键词后仍返回默认列表。
- 已加关键词守卫：某站点一次返回 ≥5 条且标题全不匹配关键词时，整批丢弃并标 `irrelevant`（BUG-008 已关闭）。
- Torrent Downloads 的 403 是参数顺序触发：`s_cat` 打头返回 403，`search` 打头返回 200。查询构建器原先按字母序排列，改为「关键词参数优先 + 其余按定义声明顺序」，问题消失（BUG-009）。
- Uindex 的 403 是 Cloudflare 交互式挑战，无法用 HTTP 客户端通过；已单独分类为 `challenge`（错误码 42204），提示「不支持绕过，请换站点」，不再误报成认证失败（BUG-010）。
- Mikan/TPB 在连续测试后触发限流，冷却机制按预期生效（连续 3 次失败进入冷却）。

### 测试过程中修复的真实兼容问题

1. Scriban 模板：引号内正则转义（`\d`）导致解析失败。
2. `{{ .Config.cat-id }}` 等带连字符的键无法解析。
3. YAML 把 `0_0` 解析成数字 0，导致分类默认值丢失（改为保留原始标量）。
4. 定义设置默认值未注入实例（如 `apiurl`、`filter-id`）。
5. 独立 API 主机（apibay.org）不在 links 白名单内；重定向也未校验白名单。
6. 部分站点要求 `Referer` 才返回结果。
7. 403 被误判为认证失败，改为“站点拒绝访问（可能被反爬拦截）”。

## 3.5 人机验证站点（REQ-28）

Uindex 的 403 是 Cloudflare 交互式挑战，HTTP 客户端无法通过。按 D-09 的处理方式，实现了「导入用户已完成验证的会话」：

| 路径 | 说明 |
|------|------|
| 站点编辑表单 | 粘贴 Cookie（至少 `cf_clearance`）与同一浏览器的 User-Agent |
| 浏览器扩展 | `tools/bujic-cookie-import/`，一键复用当前 Bujic Movie 页面的登录态后按域名导入，无需手填地址与令牌 |
| 接口 | `POST /api/v1/search/cookie-import`，按域名匹配站点；多命中返回候选 |

安全与一致性：Cookie 加密落库、读接口只回名称；`cf_clearance` 绑定 IP + UA，界面与 README 都写明服务端与浏览器必须同出口 IP。

实测：用一个「无 Cookie 即返回 403 + `cf-mitigated: challenge`」的桩站点验证了完整闭环——导入前分类为 `challenge`，导入后测试通过。
