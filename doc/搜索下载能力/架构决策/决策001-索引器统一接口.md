# ADR-001 索引器接入用统一 Connector 接口，双实现

状态：已接受 ｜ 日期：2026-11-19 ｜ 关联：REQ-01、REQ-04、REQ-07、NFR-08

## 背景

PRD 要求同时支持通用 Torznab/Newznab 与 Cardigann YAML 两类索引器。搜索、测试、能力识别、下载链接解析四条链路都必须对两类索引器一致；新增类型不应该改搜索主流程。

## 选项

| 选项 | 扩展成本 | 一致性 | 复杂度 | 结论 |
|------|----------|--------|--------|------|
| 搜索层写 if/else 分支 | 每加一类改主流程 | 低 | 低 | 否决（违反 NFR-08） |
| 每类索引器独立服务与路由 | 低 | 低 | 高（三套截止/去重/错误） | 否决 |
| 统一 Connector 接口 + 两实现 | 低 | 高 | 中 | **采纳** |

## 决策

定义 `Connector` 接口：

```
type Connector interface {
    Test(ctx) (Capabilities, error)
    Search(ctx, Query) ([]Release, error)
    ResolveDownload(ctx, Release) (DownloadRef, error)
}
```

`TorznabConnector` 与 `CardigannConnector` 各自实现；`SearchService` 只依赖接口与 `Release` 归一化模型。

## 代价

- 接口要容纳 XML（Torznab）、HTML（Cardigann）、JSON（Cardigann JSON 站点）三类返回，`Release` 字段需要允许缺省（做种数、分类、发布时间可空）。
- 特殊站点行为只能落在实现内部，接口不允许出现"仅某站点"的字段。

## 影响

- 搜索与推送的测试可用统一 fake connector，不必起站点。
- 新增 Usenet 或其它协议时只加实现，不动 CMP-08。
