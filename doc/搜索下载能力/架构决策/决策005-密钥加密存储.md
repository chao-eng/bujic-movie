# ADR-005 凭据用 AES-256-GCM 加密，密钥由 server.secret_key 派生

状态：已接受 ｜ 日期：2026-11-19 ｜ 关联：REQ-01、REQ-11、NFR-07

## 背景

站点密钥、账号密码、下载器密码、代理凭据、登录 Cookie 都必须落库，但接口不能回显明文，日志不能出现明文。项目已有 `server.secret_key`，用于 JWT 签名。

## 选项

| 选项 | 密钥管理 | 轮换 | 依赖 | 结论 |
|------|----------|------|------|------|
| 明文存储 | 无 | — | 无 | 否决 |
| 复用 JWT secret 直接加密 | 简单 | 改 secret 即失效 | 无 | 否决（域未分离） |
| 独立随机主密钥文件 | 需新增文件与备份 | 需迁移 | 文件权限 | 否决（违反单文件备份） |
| server.secret_key 经 HKDF/SHA-256 派生专用子密钥 | 无新增 | 改 secret 需重录 | 无 | **采纳** |
| 系统 keychain | 平台相关 | 支持 | 平台 | 否决（跨平台） |

## 决策

- `crypto.SecretBox`：`key = SHA-256("bujic.search.secret.v1" || server.secret_key)`；AES-256-GCM；存储格式 `base64(nonce(12) || ciphertext || tag)`。
- 需要加密的字段：`indexers.api_key_enc`、`secrets_enc`（含代理凭据）、`download_clients.api_key_enc/password_enc`、`indexer_sessions.cookie_enc`。
- 读接口只返回掩码：`**** + 末 4 位`；更新时若提交值等于掩码哨兵 `__unchanged__`，保留原值。
- 解密失败（密钥变更/数据损坏）：视为未配置，记一条 WARN（不含密文），要求用户重新填写；不影响启动与其它配置。

## 代价

- 修改 `server.secret_key` 会导致所有已存凭据不可解，需要重录；这是安全与可运维之间的取舍，已在界面提示。
- 加密/解密在请求路径上，单次 <1ms，可忽略。

## 影响

- 测试需覆盖：掩码读取、哨兵保留、解密失败降级、日志无明文。
- 安全审计以"日志与响应中是否出现明文"为判据，不检查数据库内部格式。
