# ADR-009 解析库选型：goccy/go-yaml + goquery + gjson

状态：已接受 ｜ 日期：2026-11-19 ｜ 关联：REQ-02、REQ-09、NFR-08

## 背景

Cardigann 定义需要三类解析：YAML（定义本身）、HTML（多数站点列表页）、JSON（部分站点 API）。项目当前只有 YAML 的间接依赖（viper 引入），没有 HTML 选择器或 JSON path 能力。

## 选项

| 领域 | 选项 | 体积/依赖 | 能力 | 结论 |
|------|------|-----------|------|------|
| YAML | `gopkg.in/yaml.v3` | 小 | 稳定、结构体映射 | 备选 |
| YAML | `github.com/goccy/go-yaml` | 中（已在依赖树） | 支持严格模式与路径错误 | **采纳** |
| HTML | 自写 `x/net/html` 遍历 | 零新增 | 需实现 CSS 选择器 | 否决（成本高） |
| HTML | `github.com/PuerkitoBio/goquery` | 小 | CSS 选择器 + 属性/文本 | **采纳** |
| JSON | `encoding/json` + 自写路径 | 零新增 | 需实现 a.b[0].c | 否决 |
| JSON | `github.com/tidwall/gjson` | 小 | 现成路径语法 | **采纳** |

## 决策

- YAML：`goccy/go-yaml`，开启严格字段检查；未知字段不报错但记录到 `compat_detail`（区分"未支持"与"拼写错误"）。
- HTML：`goquery`，选择器语法与 Cardigann 的 CSS 选择器一致。
- JSON：`gjson`，支持 `data.items.#.title` 一类路径。
- 三个库都通过 `definitionparser` 与 `cardigann` 包隔离，不扩散到 service 层。

## 代价

- 新增 2 个直接依赖（goquery、gjson），YAML 库转为直接依赖；二进制体积预计增加 1–2MB，仍在 NFR-12 的 8MB 预算内。
- goquery 对大页面（>5MB）解析内存偏高，靠 BR-39 的 20MB 响应上限与流式读取约束。

## 影响

- 解析器单测用 YAML/HTML/JSON fixture，不需要真实站点。
- 库升级只影响 `cardigann` 包，不影响搜索与下载主流程。
